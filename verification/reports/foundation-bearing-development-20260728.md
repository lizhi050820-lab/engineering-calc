# 地基承载力规范验算开发记录

## 1. 实现功能

新增“地基承载力规范验算”，已接入首页、土力学分类页、页面路由、浏览器 JavaScript 计算核心和 FastAPI。

第一版支持：

- GB 50007—2011 表5.2.4常用土类 ηb、ηd 查表；
- 自定义承载力修正系数；
- fₐₖ 的基础宽度、埋深修正；
- 矩形基础轴心、单向偏心和双向偏心压力；
- 自动估算或手动输入基础与覆土重 Gₖ；
- pₖ≤fₐ 和 pₖ,max≤1.2fₐ 自动判断；
- 单向大偏心三角形接触压力；
- 双向偏心脱空识别与专项复核提示；
- 四角压力示意、逐步中文计算和理论边界。

## 2. 原理说明

按 GB 50007—2011：

- fₐ = fₐₖ＋ηbγ(b₀－3)＋ηdγm(d₀－0.5)
- pₖ = (Fₖ＋Gₖ)/A
- 全截面受压时，pₖ,max/min = (Fₖ＋Gₖ)/A ± Mₖ/W
- 单向偏心 e＞b/6 时，pₖ,max = 2(Fₖ＋Gₖ)/(3la)

修正用基础宽度 b₀ 限制在 3～6 m；实际埋深小于 0.5 m 时按 0.5 m 计算，避免产生负深度修正。双向偏心出现角点拉应力后，简单线性外推已不是真实接触压力，因此页面不继续输出虚假的 pₖ,max。

## 3. 决策记录

- 第一版只做天然地基承载力和基底压力，不混入沉降、软弱下卧层、抗滑、抗倾覆、冲切和配筋。
- 用户必须输入来自勘察或试验的 fₐₖ；程序不根据土名猜测承载力。
- 表5.2.4只自动查 ηb、ηd，同时保留自定义系数，适应勘察报告给定值。
- Gₖ 提供自动估算和手动输入两种方式，权威算例使用原资料给出的 Gₖ。
- 单向脱空按规范三角形压力继续计算；双向脱空不采用缺乏依据的简化公式。
- 网页端与 Python 参考端独立实现，并使用固定随机种子进行差分验证。

## 4. 问题与修复

### 问题一：自定义系数空值被当成零

JavaScript 的空值默认处理曾将缺失的 ηb、ηd 转成 0，导致自定义土类在未填写系数时仍可计算。已增加显式空值检查，并加入永久非法输入测试。

### 问题二：新后端测试没有进入旧式测试运行器

项目测试文件不是 pytest 自动发现，而是在文件末尾手动实例化测试类。首次运行仍显示 60/60，说明新增测试未执行。已把 `TestFoundationBearing` 加入运行器，最终为 62/62。

### 问题三：性质测试误用了已舍入面积

“竖向力增加—平均压力线性增加”性质测试曾用显示为三位小数的面积计算理论值，造成 1/3300 的假失败。改为使用原始 b·l 计算期望值后，3300/3300 通过；没有通过放宽不合理容差来掩盖问题。

### 问题四：普通文字定位没有切换荷载输入模式

浏览器验收时，点击内部文字节点未可靠触发“自动估算 Gₖ”。改用带文字条件的完整选项容器后切换成功，确认这是测试定位问题，不是页面事件错误。

### 问题五：GitHub Actions 缺少 Python 依赖

过去的发布流程只运行 JavaScript 测试和 H5 构建，不会导入 Python 计算器。增加全项目差分门禁后，干净的 Ubuntu 运行器首次执行验证器时出现 `ModuleNotFoundError: numpy`。

修复方法是在工作流中增加 Python 3.12、pip 缓存和 `backend/requirements.txt` 安装步骤，并把 62 项 Python 后端回归也纳入云端门禁。这个问题说明：本地虚拟环境已安装依赖，不代表每次新建的 CI 运行器也具备相同环境。

## 6. 本次收获与下一步

地基承载力不只是比较一个压力和一个承载力。偏心荷载可能改变接触范围，某些工况下继续套用线性公式会产生土体“受拉”的假结果。程序应当识别理论失效，而不是为了给出数字强行计算。

下一步建议开发“分层总和法沉降计算”，使地基模块从承载力验算扩展到变形验算；软弱下卧层可作为随后独立工具。
