# 钢筋工程速算功能开发记录

## 1. 实现功能

新增“钢筋工程速算”，注册到混凝土结构设计分类页、首页计数、页面路由、浏览器本地计算入口和 FastAPI。

第一版包括：

- 单根长度、根数与理论总重量计算；
- 已知总重量反算等效总长度；
- 按首末筋中心布置长度和最大允许间距计算根数、实际间距与重量；
- 不同标准直径钢筋的等面积代换；
- Φ6～Φ50 公称面积和理论单位重量查表；
- 中文公式步骤、适用范围和风险提示。

## 2. 原理说明

GB 1499.1—2024、GB 1499.2—2024 表2给出标准规格钢筋的公称横截面面积与理论单位重量，理论重量按钢密度 7.85 g/cm³确定。

- 总长度：L = l·n
- 理论总重量：G = m₀·L
- 重量反算长度：L = G/m₀
- 间隔数：nᵢ = ⌈L₀/sₘₐₓ⌉
- 排布根数：n = nᵢ＋1
- 实际间距：s = L₀/nᵢ
- 等面积代换：n₂ = ⌈n₁A₁/A₂⌉

间距计算中的 L₀ 明确定义为第一根与最后一根钢筋中心之间的距离，避免把构件总宽度、保护层和钢筋中心位置混为一谈。

## 3. 决策记录

- 第一版只采用国家标准表2的标准直径，不允许输入任意非标准直径。
- 使用标准表列理论单位重量，不用口算常数 d²/162 替代表值。
- 等面积代换只给出面积结果，不宣称自动完成设计变更。
- 暂不加入锚固、搭接和弯钩下料，因为这些还需要构件部位、抗震等级、连接率等条件。
- GitHub Pages 使用 JavaScript 本地计算；Python 保持独立实现，作为 API 和差分参考。

## 4. 问题与修复

### 问题一：间距根数不能简单向下取整

若按 `floor(L₀/s)+1` 计算，当 L₀ 不能被 s 整除时，实际间距会超过用户输入的最大允许值。程序改用 `ceil(L₀/s)+1`，并增加“实际间距不得大于允许最大值”的性质测试。

### 问题二：舍入临界值出现 0.1 mm² 差异

首轮 5000 组差分虽然在钢筋面积一位小数容差内全部通过，但报告显示 Python 与 JavaScript 在少数 `x.x5 mm²` 临界值相差 0.1 mm²。没有依靠容差放行，而是统一明确的四舍五入修正量，并把面积字段差分容差收紧到 0.0011。重新验证后最大误差为 0。

### 问题三：等面积不等于可直接代换

面积满足仍可能违反间距、净距、锚固、搭接、裂缝和构造要求。页面将这一点作为醒目风险提示，不把计算结果描述为自动设计结论。

## 5. 验证结果

- GB 1499.2—2024 表2 Φ16：A=201.1 mm²、m₀=1.58 kg/m；
- 25根、每根6 m：L=150.000 m、G=237.000 kg；
- 固定、边界和非法输入测试：全部通过；
- 权威发布门禁：7/7 通过；
- 新工具 5000 组差分＋3400 项数学性质：8400/8400 通过，最大误差 0；
- 全项目 Python/JavaScript 差分和性质验证：9400/9400 通过；
- Python 后端与 API：66/66 通过；
- H5 正式构建：通过。

## 6. 本次收获与后续

看似简单的现场速算仍需要精确定义输入边界。例如“布置长度”如果不说明是构件长度还是首末筋中心距，根数就可能相差一根。工程工具的可靠性不仅来自公式，还来自清晰的输入定义、向上取整规则和结果适用范围。

后续可以根据真实使用反馈增加多组钢筋清单汇总和 CSV 导出，但应继续避免把条件不足的锚固、搭接计算包装成一键答案。
