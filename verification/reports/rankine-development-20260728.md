# 朗肯土压力功能开发记录

## 1. 实现功能

新增“朗肯土压力”计算工具，已注册到土力学分类页、首页工具数量、页面路由、浏览器计算 API 和 FastAPI。

第一版支持：

- 主动、被动、静止三种状态；
- 1～8 层土，逐层输入 h、γ、φ、c 和 γₛₐₜ；
- 地面均布荷载 q；
- 可选地下水位；
- 水土分算与水土合算；
- 分段压力、土压力合力、水压力合力、总合力和合力作用点；
- 中文计算步骤、公式依据、理论假定和不适用情形。

## 2. 原理说明

经典朗肯系数：

- Kₐ = tan²(45° − φ/2)
- Kₚ = tan²(45° + φ/2)
- K₀ = 1 − sinφ

主动土压力按 pₐ = Kₐσᵥ − 2c√Kₐ，被动土压力按 pₚ = Kₚσᵥ + 2c√Kₚ。主动状态出现负压力时按零处理，不把土体当作可以承受拉应力。

程序把墙高按土层界面、水位和主动压力零点切成若干线性分段，对每一段精确积分面积与对墙底力矩，因此既能求合力，也能求合力作用点。水土分算时，水下土体使用浮重度计算有效应力，孔隙水压力再单独叠加。

## 3. 决策记录

- 第一版采用朗肯理论，不扩展到库仑土压力、地震土压力和支护结构变形分析，保持“快速计算”的产品定位。
- 网页正式计算使用 JavaScript，保证 GitHub Pages 无后端也能运行；Python 保留为独立参考实现与 API。
- 多层土采用分段积分，而不是把各层等效成单层，避免丢失层间压力突变及作用点信息。
- 公开算例选用武汉理工大学课程例题，不用程序自行生成的数据冒充权威证据。
- 对水土分算/合算给出文字说明，由使用者依据土类和工程条件选择，不在信息不足时自动替用户作工程判断。

## 4. 问题与修复

### 问题一：只有随机算例不能证明公式来源正确

Python/JavaScript 两套实现即使一致，也可能复制同一个理论错误。为此增加武汉理工大学两层砂土例题作为固定发布门禁，并记录来源、参数、单位、期望值与容差。

### 问题二：开启地下水后旧结果仍显示

切换地下水只改变输入状态，不应把旧结果误认为新结果。页面实测时重新点击“开始计算”，核对水压力从 0 变为 313.920 kN/m、总合力变为 570.236 kN/m，并确认分算结果和步骤同步更新。

### 问题三：Windows 校验脚本默认编码

Skill 校验器在 Windows 默认 GBK 环境读取 UTF-8 中文时出现解码错误。使用 `PYTHONUTF8=1` 后校验通过；这属于开发工具环境问题，不是计算逻辑问题。

### 问题四：微信小程序端地下水开关无法保持开启

地下水区域外层 `switch-row` 绑定了点击翻转，内部原生 `switch` 又通过 `change` 事件写入状态。在微信小程序端点击开关时两个事件会先后执行，使 `waterEnabled` 可能刚开启又被关闭。修复时移除外层重复点击，只保留原生 `switch` 的 `change` 事件作为唯一状态来源，并增加页面源码回归断言，防止以后重新引入双重切换。

- 全项目 Python/JavaScript 差分与数学性质测试：7400/7400 通过；
- Python 后端与 API 回归：60/60 通过；
- 手机宽度网页实际输入与地下水交互：通过；
- H5 正式构建：通过；
- `calculation-verifier` Skill 结构校验：通过。

## 6. 本次收获与后续

这次不仅实现了公式，还建立了“权威算例 + 独立实现 + 随机差分 + 性质测试 + 页面实测”的证据链。需要继续补充的是带黏聚力的教材算例、水土合算的权威算例，以及与地下水有关的更多分层边界情况。

下一步可优先扩展土力学工具：地基承载力规范法；随后再做朗肯模块的库仑修正或挡土墙稳定验算，但这些应保持为独立工具，避免把快速计算页面变成复杂建模软件。
